# Manual Clip Mode Design

**Date:** 2026-07-18
**Status:** Approved

## Goal

Produce a Short from a YouTube link and a start timestamp that the user
supplies, instead of picking a trending video and a heatmap/motion window. The
existing daily trending pipeline is unchanged and continues to run on cron.

## Scope decisions

- **Additive.** Manual mode is a new entrypoint alongside the auto pipeline, not
  a replacement.
- **Captions = existing on-screen text.** The clip carries the same LLM-written
  hook and the source credit line the auto pipeline already renders. No audio
  transcription and no subtitle track are added.
- **Fixed 35-second clip.** The user gives one start timestamp; the clip is
  always `CLIP_SECONDS` (35s), preserving the current output-duration guarantee.
- **Auto metadata.** Title, description, hashtags, and the on-screen hook are
  generated by the existing `gen_metadata` LLM call from the source video's
  title and channel.

## CLI

```
pipeline.py --url <youtube-url> --start <timestamp> [--dry-run]
```

- When `--url` is present, the pipeline runs manual mode.
- Otherwise it runs the existing trending loop, untouched.
- `--start` accepts `90`, `1:30`, or `1:02:03`.
- `--dry-run` uploads privately; the default is public.

## New helpers (pure, unit-tested)

- `parse_video_id(url)` — extracts the 11-character id from `watch?v=`,
  `youtu.be/`, and `shorts/` URL forms. Raises `ValueError` on anything else.
- `parse_timestamp(ts)` — parses `SS`, `MM:SS`, or `HH:MM:SS` into seconds.
  Raises `ValueError` on malformed input or negative values.

## `run_manual(url, start_seconds, privacy)`

1. `parse_video_id(url)` then `download(video_id)`; the returned `info` dict
   provides the source `title` and `uploader` (channel), so no trending-API item
   is required.
2. Clamp the start to `[0, max(0, duration - CLIP_SECONDS)]` using the source
   duration from `info`, preserving the 35s output guarantee.
3. `gen_metadata(title, channel, url)` → title, description, hashtags, hook.
4. `edit(src, start, hook, "Credit: <channel>", out)` → `self_check(out)` →
   `upload(out, meta, privacy)`.
5. `log_run` the result with `method: "manual"`. **Do not** touch
   `used_videos.json`; manual clips are deliberate and may reclip a source.

## Error handling

- A malformed `--url` or `--start` exits with a clear message before any
  download. There is no candidate loop to fall through to.
- Download, metadata, edit, self-check, and upload raise as they do today; a
  failure aborts the single manual run with a non-zero exit.

## GitHub Actions: `clip.yml`

A new `workflow_dispatch`-only workflow that mirrors `daily.yml`'s environment
(self-hosted mac runner, local venv, deno, keg-only `ffmpeg-full` on PATH,
Brave cookie export, the same secrets and `USE_RENDERED_HEATMAP` /
`BRAVE_EXECUTABLE` env). It has no cron trigger.

Inputs:

- `url` (string, required)
- `start` (string, required)
- `dry_run` (boolean, default false)

Run step: `pipeline.py --url "<url>" --start "<start>"`, with `--dry-run` added
when `dry_run` is true. The exported cookie file is removed on `always()`.
There is no "commit state" step because manual mode persists no state.

## Testing

Unit tests:

- `parse_video_id`: `watch?v=`, `youtu.be/`, `shorts/`, extra query params, and
  junk input (raises).
- `parse_timestamp`: `SS`, `MM:SS`, `HH:MM:SS`, and junk/negative (raises).
- Start clamping: start past `duration - CLIP_SECONDS` clamps to the end; a
  source shorter than `CLIP_SECONDS` clamps the start to 0.

Integration test: `run_manual` with `download`, `gen_metadata`, `edit`,
`self_check`, and `upload` monkeypatched — asserts it clips at the parsed start,
uploads exactly once, logs `method: "manual"`, and leaves `used_videos.json`
untouched.

Workflow test: assert `clip.yml` exists, is `workflow_dispatch`-only, declares
`url`/`start`/`dry_run` inputs, and runs on the self-hosted mac runner.

## Out of scope (YAGNI)

Audio transcription, burned-in spoken-word subtitles, custom clip length,
start+end ranges, and manual metadata overrides. None are built.
